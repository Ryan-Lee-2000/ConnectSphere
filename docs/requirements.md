# Release 1 requirement boundary

Authoritative order: customer briefing, Week 4 instructions, answered GitHub Discussions,
team decisions labelled as proposals. Unanswered forum questions are not requirements.

All 20 areas must form coherent workflows: authentication/authorisation; event request creation;
drafts; review/approval; Coordinator assignment; event status; event information; venue catalogue;
venue availability; venue search/filtering; venue suitability; booking request; booking approval;
conflict detection; equipment request; equipment availability; equipment reservation; attendee
registration; event change requests; notifications.

Rules that future product stories must respect:
- one person may have multiple roles;
- responsible Organiser may edit; same-client Organisers may view; unrelated clients cannot view;
- accounts may be assumed to exist; onboarding/password recovery are not current core requirements;
- Coordinator assignment follows submission and is entered manually by Operations Manager;
- approval permits planning; confirmation requires all event-specific essential arrangements;
- multi-session events are confirmed and the future schema must not preclude them.

Before implementing a Product Backlog item, copy its exact acceptance criteria and linked customer
answer into the task/issue. Recheck https://github.com/SinYang13/IS212-2026/discussions because
answered posts become project requirements. Replace this concise file with the maintained full
baseline when creating the actual repository.
