# SPL-124 build handoff

Branch: `feature/SPL-124-registered-event-notices`, based on main `b848663` (after SPL-121).

| AC | Implementation |
| --- | --- |
| 1 | Date and time: `significant_event_changes.apply_prepared_change` calls `notifications.add_schedule_change_notices` after saving the change record, for event-level changes only; SPL-112's accepted items reach the same helper. Venue: `venue_booking_approvals.approve_venue_booking` and `venue_arrangements.cancel_venue_booking` call `notifications.add_venue_change_notices`. |
| 2 | `event_cancellation.cancel_event` calls `notifications.add_attendee_notices` (kind `event_cancelled`). |
| 3 | `event_registrations.register_for_event` and `withdraw_registration` call `notifications.add_registration_notice`. |
| 4 | Each notice is added in the action's transaction, after its checks; the unique (recipient, dedupe key) index stops a repeat. Registration flushes inside its existing `IntegrityError` backstop, so a racing duplicate rolls back its notice too. |
| 5 | `notifications.add_attendee_notices` reads the Registered registrations at the time of the action. |
| 6 | `notifications._event_link` sends `attendee_` notices to `/workspace/my-registrations`; `frontend/src/Notifications.tsx` accepts that link. |
