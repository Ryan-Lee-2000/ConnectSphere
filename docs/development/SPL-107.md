## Delivered behaviour

The existing Venue calendar now offers One venue and All venues views. All venues reads one Singapore date through `GET /api/venues/occupancy-overview?date=YYYY-MM-DD`, with every venue included. Quarter-hour guides preserve exact booking/setup/turnaround/closure boundaries, including arbitrary-minute buffers. Normally closed time and unconfirmed timing never appear as available operating time.

Selecting a venue gives a readable list of periods; selecting a period exposes every overlapping cause, original timing and generic review warning. The timeline has keyboard controls and a phone-friendly text equivalent. Date changes, empty dates, failed requests, refresh and role changes discard stale data/detail.

The route reuses `exact_calendar`, shared interval/closure readers and `exact_review_reasons`. Both exact calendar APIs now include persistent/dynamic review markers, and the existing single-venue UI also displays the warning. Flagged bookings retain occupancy. No second occupancy engine, business write, table or migration was added.

The API allowlist remains Venue Staff, Event Coordinator and the existing manager/Lead role. The server provides event names and links only for existing staff access or a currently assigned coordinator. Closure free text is staff-only here; assigned coordinators retain their existing affected-booking detail route. An unrelated coordinator or Lead gets anonymous occupancy. Destination endpoints recheck access, including after reassignment; the UI additionally filters links to the selected role.
