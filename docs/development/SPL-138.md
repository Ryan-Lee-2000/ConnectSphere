Local implementation on codex/SPL-138-timed-closures, updated to main 4d05da2ad849c19c0911f8a213c17c93bb5252e8 after PR #63 merged. Current Jira criteria were supplied by Ryan in this conversation and match docs/tasks/SPL-138.md. No scope or estimate change.

## Behaviour

Venue Staff can create precise SGT closures and remove them with retained audit evidence. Closures immediately participate in the existing exact and legacy conflict paths. Overlapping active bookings keep their status and snapshots and receive review markers. Removal clears only that closure's availability effect.

The existing per-venue calendar renders event/setup/turnaround/closure intervals without enlarging them into legacy slots. It preserves historical booking snapshots and distinguishes closed/unknown configuration from free operating time. Shared calendar reasons are anonymous; authorized booking details include the exact closure interval.

## Schema and rollout

One additive migration, s3_timed_venue_closures, now follows s3_equipment_catalogue (merged PR #63). Nullable exact_start/exact_end have an all-null or ordered-pair constraint; legacy records and RLS remain unchanged. Confirm the latest main parent again before merge.

EXACT_VENUE_TIMING_ENABLED remains false by default. It was enabled only in local test configuration. Hosted deployment, hosted migrations and release activation were not performed. Notifications, replacement arrangements, assessment UI and multi-venue creation remain their owning stories; this implementation does not claim those release obligations are complete.
