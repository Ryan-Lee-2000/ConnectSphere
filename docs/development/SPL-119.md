# SPL-119 — View registered attendees

## Scope and behaviour

The Event Organiser's existing read-only organisation-event detail now includes a registration
list for a submitted event in the organiser's own organisation. The panel shows the active
registration count against capacity and each attendee's name, email, contact number and special
requirements. Withdrawn registrations are shown in a separate labelled table and never increase
the active count. When registration is disabled, the panel explains that state instead of
presenting an empty attendee list. Export remains outside this story.

The endpoint preserves SPL-110's access boundary: only the Event Organiser role may read it, the
event must be submitted, and a cross-organisation event or private draft returns the same generic
404. The response uses an explicit attendee-field allowlist and does not expose registration
audit metadata. The frontend capability-gates the request so it remains compatible while backend
and frontend revisions overlap during a rolling deployment.

## API contract

`GET /api/organisation/events/{event_request_id}/registrations`

The response contains `registration_list` with `enabled`, `capacity`, `registered_count`,
`registered` and `withdrawn`. Each attendee contains only `id`, `name`, `email`, `contact_number`
and `special_requirements`. Active and withdrawn rows are ordered deterministically by registration
time and ID. The existing organisation-event response advertises support through the
`X-ConnectSphere-Registration-List: available` header.

No database migration or write endpoint is introduced.
