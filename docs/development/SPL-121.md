## QA finding D1 (22 October 2026)

QA's integration run found a deadlock: the existing SPL-98 case
`test_tc_spl_98_12_event_release_and_unavailability_do_not_deadlock` failed with
`DeadlockDetected`. Cause, shown by running that case with and without the AC4 notice: a notice
references its event, so inserting one takes a KEY SHARE lock on the event row. The units route
holds the stock-pool lock at that point, while SPL-98's event-wide release held the event in full
FOR UPDATE mode and waited for the same pool. Every other lifecycle lock (cancellation,
confirmation, SPL-93) already uses FOR NO KEY UPDATE, which KEY SHARE never conflicts with.

Fix, approved by Clive: `equipment_releases._locked_planning_event` now takes FOR NO KEY UPDATE.
It still blocks any status change during a release. The SPL-98 case passes unchanged, and so does
the full integration suite (138 passed). Recorded as D1 in QA-SPL-121.
