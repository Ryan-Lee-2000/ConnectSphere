# SPL-104 development handoff

Task and decisions: [docs/tasks/SPL-104.md](../tasks/SPL-104.md).

## Implementation

- `backend/app/notifications.py`: `add_venue_booking_notices` writes one notice per active Venue
  Staff account for a requested or withdrawn booking, in the caller's transaction, keyed
  `venue_booking_<kind>:<booking id>`. `_booking_details` formats the date, Singapore times and
  occupied window from the booking's exact timing, or from its slots when exact timing is off.
  A Requested booking stored without timing (SPL-83 claims) gets a notice without details, so it
  can still be withdrawn (QA defect D1, case QA-SPL-104-067).
  `_active_role_holders` is shared with `add_technical_support_notices`. `_event_link` sends
  `venue_booking_` notices to `/workspace/booking-requests`.
- `backend/app/venue_booking_requests.py`: both request paths (slot and exact) call the helper
  before commit.
- `backend/app/venue_booking_withdrawals.py`: the withdrawal calls the helper before commit.
- `frontend/src/Notifications.tsx`: the link allowlist accepts `/workspace/booking-requests`.

No migration and no new dependency.
