## Review round 1 (22 October 2026)

Ryan's P2 on PR #96: a retried addition created a second line and a second notice, which AC4
forbids. Fix, approved by Clive (client request key):

| Change | Where |
| --- | --- |
| The Add form makes one request id when it opens and sends it with every save attempt of that form. | `EquipmentRequirements.tsx` |
| The add route accepts an optional `request_id` (a UUID). After the event lock, a request id already used on that event returns the existing line with 200: no second line, no second notice. | New nullable column `equipment_requirements.request_id`, unique per event, so the database also refuses a second line for one request. | `models.EquipmentRequirement`, migration `s4_equipment_request_ids` |

This round adds a migration, so "No migration" above no longer holds. The migration is additive
and nullable; existing lines keep a null request id. Regression cases QA-SPL-122-047 to 049
(backend), 055 (frontend) and 074 (PostgreSQL race); see QA-SPL-122.
