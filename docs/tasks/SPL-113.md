# SPL-113 — See the outcome of my change request

Source: [Jira SPL-113](https://clivelim01-1787647390567.atlassian.net/browse/SPL-113).
Sprint 4; original estimate retained: 2 points. Depends on merged SPL-112, SPL-111 and SPL-141.

## Acceptance criteria

1. Each item shows Pending, Accepted or Declined with the reason where declined.
2. Closed requests remain viewable as history.
3. Accepted values are visible on the event.
4. An organiser from another organisation cannot see the request.

Customer Q104, rechecked 31 October 2026, permits partial acceptance and requires the organiser
to receive the reason or follow-up for a declined item; presentation may be proposed by the team.
Source: https://github.com/SinYang13/IS212-2026/discussions/104

## Approved decisions

- Retain owner-only organiser request access and assigned-coordinator access. Organiser reads
  additionally require current membership in the event's organisation. Colleagues gain no
  change-request access.
- Show the pending request first, then Closed history in the API's newest-first order.
  History remains reachable for every non-draft event status; submission rules stay unchanged.
- Historical values are labelled At submission in the organiser view, not Now.
- Current event details show layout, facilities, accessibility needs and venue preferences/notes.
  Equipment technical notes are visible only to the responsible organiser. Internal event notes
  and Venue Staff approval notes remain excluded. Ryan approved this owner/colleague distinction.
- Reopening/reloading fetches saved state. No polling, new notices or migration; SPL-123 owns
  item-decision notices and SPL-112 owns decision application and closure.
- Ryan approved targeted updates to QA-SPL-111-109 (snapshot label), QA-SPL-111-113 (history
  entry availability), and TC-SPL-110-006 (retain colleague privacy and check owner-only notes).
  The snapshot test was initially misidentified as 110 in the approval question and corrected
  to 109 before editing. QA-SPL-111-110 remains unchanged.
- Ryan also approved adding only the four new current-detail fields to SPL-45's exact JSON
  response assertion in `test_tc_cs_e01_s3_02_opens_the_approved_read_only_detail`.
- Ryan approved the one-line SPL-125-015 test portability fix: render its temporary path with
  `as_posix()` when embedding it in subprocess Python source; all assertions remain unchanged.

## Implementation

- `ChangeRequests.tsx`: organiser item outcomes and Closed history.
- `EventRequestDrafts.tsx`: history access for submitted events and link to current details.
- `OrganisationEvents.tsx` and `event_requests.py`: current accepted fields and owner-only notes.
- `event_change_requests.py`: current organisation membership for organiser reads.
