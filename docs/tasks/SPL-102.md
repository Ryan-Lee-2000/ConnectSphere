# SPL-102 — CS-E20-S2: Be notified of my request's review outcome

**Epic:** CS-E20 Notification System
**Estimate:** 3 story points
**Depends on:** SPL-101 (inbox), SPL-134 (assignment notices)

## User story

As an Event Organiser, I want to be notified of the outcome of my event request review so that I
can act on it without having to check the status myself.

## Acceptance criteria

1. **Assignment:** Given my event request is assigned or reassigned to a coordinator, then I receive
   a notification naming the event.
2. **Clarification requested:** Given a coordinator requests clarification on my request, then I
   receive a notification naming the event and including the coordinator's message.
3. **Decision:** Given my request is approved or rejected, then I receive a notification naming the
   event. A rejection includes the reason.
4. **Withdrawal:** Given my request is recorded as withdrawn, then I receive a notification naming
   the event.
5. **No false notices:** A refused or repeated action creates no notification, and only the
   organiser of that event is notified.

## Implementation

- AC1 is delivered by SPL-134's `add_assignment_change_notices`; SPL-102 adds nothing to it.
- `notifications.add_review_outcome_notice()` is called from the existing clarification, approve,
  reject and withdraw actions in `event_review.py`, in the same transaction as the action.
- The recipient is the organiser stored on the event. Dedupe keys use the clarification or status
  history row id, so a repeat cannot add a second notice.
- No migration, endpoint or frontend change. Out of scope: begin-review, the organiser's response,
  confirmation and coordinator notices.
